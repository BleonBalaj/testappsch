# School workflows implementation

Scope: supply requests and repairs in School Requests; shared lesson-plan comments and review management; dated teacher absence and substitute coverage. No reservations or parent journal.

## Contracts

- Primary checkout on main, no commits/staging. Browser testing remains prohibited. Release once after app, functions, rules and emulator checks.
- All workflow mutations run through an authenticated callable with active tenant membership, module permission, canonical record links, expected revisions, command idempotency and immutable audit entries. Client rules deny writes to authoritative records.
- Supply fulfilment is derived from per-item requested/provided quantities. Repair completion requires a resolution. Completed/cancelled items can be archived without deleting history. Teacher requests link only to their own taught/homeroom classes; admins manage all.
- Comments are separate from lesson paper and review management. The author and assigned admin reviewer can send plain messages while the plan is shared, including after the admin has archived their review. Sending a comment never changes review status, assignment or author content. Each message links to its immutable saved revision and creates history/unread notices. Earlier outcome/reply/resubmission records and old-client RPCs remain compatible; new UI presents messages without outcome selectors or resubmission choices. Admins never edit an author's plan. Inbox archive status and author status remain separate.
- Absences are dated exceptions, never destructive timetable edits. Affected lessons are derived from saved entries plus explicit course weekly schedules. No invented weekdays or times. Assignment requires explicit intervals; reject substitute absences, timetable conflicts and existing cover conflicts. Transactional queries/reads serialize concurrent assignments. Timetable cards show dated cover/cancellation labels. Substitute plan viewing is read-only and checks active assignment and sharing each time.
- Request, repair, affected-lesson and absence searches match the entire authorized query before pagination, with up to 40 results per page. Indexed scope/date/selector queries run on the server; additional predicates and accent-insensitive text matching continue across 200-record scans, at most 800 source records per callable invocation. The browser follows continuations automatically until 41 matches or true exhaustion, retains only result cards and cursors, and never requires manually loading unrelated records to discover a match. Deployed composite indexes include admin/teacher selector variants and newest-update invalidation queries.
- Verified list pages, details, directories, conversations and notification rows retain a scope-bound session cache while revalidating on return. Account, school, role or permission changes clear other scopes; denied access clears retained data and stale responses cannot repopulate it. Search filter caches and retained card pages are bounded. Live newest-update heads invalidate ordered searches from page one.
- All filters use FilterSelect; all covering dialogs use DialogPortal and a single scrollport. Native file/date/time inputs stay labelled. Nature overrides are screen-only and scoped; paper remains unchanged.

## Access and navigation

- School Requests is a staff-only sidebar section. Teachers see their own/assigned requests; school administrators see and manage all requests in their school. Students cannot read requests, photos, activity or notifications, submit a request, or bypass this through a stale staff identity or enabled permission setting.
- Absence & Coverage is available to teaching staff and admins. Admins record absence and assignments; teachers see their own absences and affected/assigned lessons. Students see only the public lesson arrangement in Schedule, with no private absence note or access to the coverage management section.
- Shared-plan Comments are available in personal plan actions and the editor after first sharing, and in the admin read-only shared view. Sending requires current sharing; earlier messages remain readable after unsharing or plan changes. Legacy reply/resubmit RPCs remain supported for old clients.
- Review ownership lives separately in `lessonPlanReviews`, survives unshare/reshare and author edits, and is checked transactionally before review status/outcome mutations. Admins claim themselves; replacing another admin requires an explicit reason and audited takeover. Completing a review archives the admin inbox only. Author feedback replies and resubmission never modify the reviewer identity.
- Exact feedback text, outcomes, actor and saved plan revision are immutable history entries. History edit sessions remain grouped in 30-minute actor/lifecycle windows; feedback, replies, assignments, status actions and automatic reopening remain separate.
- `lessonPlanActivityCreated` is a retryable Firestore event trigger. `reviewActivity.js` creates idempotent delivery receipts, monotonic per-user incoming history/comment heads and bell notices for authors and the assigned reviewer (all admins when unassigned). Own actions do not mark another person's unread message read. Repeated autosave notices coalesce within 30-minute buckets; all immutable events remain in history. Bootstrap seeds older activity and repairs a missing feedback mirror only from its recorded immutable revision.
- Red dots for History and Comments use independent per-user exact event cursors. A visible newest incoming entry can be acknowledged after a short reading interval, with a manual/retry option; opening the dialog alone does not clear unseen updates. Rules reject other-user, forged, future or regressing acknowledgements.
- In-app workflow notifications use a live latest-40 badge and cursor pages for older notices, plus toasts for new updates. Opening a notice marks only the clicked event version read and opens the relevant plan/request/coverage record. No external emails are sent.

## Theme boundaries

All dropdowns use FilterSelect, including platform administrator sort controls. Popups escape dialogs and calculate their layer above the ancestor backdrop. Workflow and platform dialogs are body portals; each has one scrolling body and background/focus containment. Nature uses the seasonal dialog/control palette for insets, fields and statuses, and its existing outer-card material for `.workflow-card` / `.padm-stat`. No Nature rules modify lesson paper, preview, Print or PDF.

## Lesson review navigation and reading

- Admins use two main tabs: My plans and Shared plans. Personal subnavigation/actions/totals are absent throughout Shared plans. Teachers retain their personal planning workspace.
- History always opens in a portalled drawer. Timeline/search are immediate; secondary filters and explanation are expandable. Actor, action, time and exact comments are directly readable. Changes show localized before/after values and retain intermediate snapshots within 30-minute sessions. The Comments action filter also finds legacy feedback/reply messages.
- A saved-version action opens a separate full-height viewer immediately, starting at the top. It does not append a preview below the history. Back to history restores the drawer position and focus. The saved paper keeps its canonical styling in every theme.
- Comments show newest messages first with author/admin identity and timestamp. The composer stays available in the dialog footer. A failed send retains the draft; earlier comments page backward without changing status. Review claim/status/archive actions stay on the shared-plan page.

## Validation

- `functions/schoolWorkflowCore.test.js`: quantities, derived fulfilment, repair resolution, dates/times, interval conflicts, strict teacher identity and backend/frontend schedule parity.
- `tests/rules/workflows.test.js`: real Admin SDK transactions plus authenticated client reads/writes against the Firestore emulator. Covers student and cross-school denial, converted staff becoming students, protected attachments/history, retries, stale and concurrent updates, exact feedback revisions, existing autosave/share lifecycle compatibility, private absence notes, cover conflicts, concurrent double-booking, cancellation and substitute plan access. Additional cases cover competing reviewer claims/takeovers, completion/restore, exact named feedback history, durable notice delivery, independent bounded read markers, backfill, global combined filters beyond 800 source records, equal-time result cursors and date-overlapping absence search.
- `listCache.test.js`, `searchPages.test.js`, `activity.test.js`: warm-return caching, stale response and permission purge, bounded live paging, zero-match continuation, result lookahead, scope disposal and independent unread cursors.
- `src/features/schoolWorkflows/datedSchedule.test.js`: weekly record preservation, dated decoration, manual lessons and restoration after absence cancellation.
- App and Functions suites, lint and production build are required before release. Deploy Functions, rules, indexes and Hosting together; verify the live version and asset hashes.
- Browser visuals and interactions remain unverified under the owner's instruction.
