# Application data and reliability QA — 17 October 2026

## Scope and method

Reviewed the authentication/session boundary, account and school preferences, school directory, student search/pagination/count caching, staff records, dashboard tasks and mood writes, course/student academic subscriptions, timetable/coverage, messaging, learning resources, lesson planning/curriculum, shared reviews/activity, School Requests, and platform administration. The work preserves the current page/card design and Nature styling.

The owner explicitly prohibits browser testing. This audit uses source tracing, automated application/backend tests, Firestore emulator integration tests, lint/build, authenticated production index/query-plan checks against an empty isolated scope, and deployment/asset verification. It does not certify every interactive path or rendered layout as browser-tested.

## Confirmed defects corrected

- Account/tenant data could survive an authority change, and old asynchronous auth callbacks could publish after replacement. Scoped auth state and a synchronous school session boundary now isolate records, selections, dialogs and providers.
- A staff snapshot handler performed repeat school reads, renamed administrators from creator data and could fabricate a visible admin after a failed write. Snapshot reads now publish canonical records only; creator profile repair is a separate guarded transaction.
- Students could fetch staff task records despite the page hiding them. The query and backend rules now agree on student-board scope, preserve task authorship and validate updates. Emulator tests also cover legitimate student updates within Firestore's expression budget.
- Dashboard dragging parsed string task IDs into invalid numeric IDs. IDs now stay strings. Task/mood/note forms retain drafts on failed saves and wait for acknowledgement before showing success. Related mood writes and profile-photo mirrors are atomic. Date-only task deadlines remain current through their local calendar day.
- Student multiword/combined filters previously operated on a capped candidate subset. The student callable now filters throughout the authorized collection before returning result pages; pickers follow empty intermediate scan batches. Two new composite indexes support class/course ordering. Displayed student IDs are watched for edits/deletions, and local mutations refresh the search. Existing count caches are isolated by UID as well as school/query/version.
- Cached workflow searches could reopen on an old result page. Return visits now start on page one while preserving verified content during revalidation.
- Personal planning templates/reusable entries/topics were not consistently isolated by owner. Queries and rules now enforce ownership. Cloud auxiliary reconciliation preserves source timestamps and removes known remote deletions while retaining unsent drafts.
- School curriculum mappings depended on an admin opening settings to refresh local data. Teachers now subscribe directly. Curriculum saves validate before persisting and only publish locally after acknowledgement; failed removals retain their confirmation and error.
- Failed academic/message listeners could leave stale records visible or silently look empty. They now clear failed records and show an error. Removed conversations no longer remain selected with their previous thread. Independent academic subscription errors clear independently after recovery.
- Missing server metadata events could skip profile backfill/live-query initialization. Metadata-sensitive listeners now request those events. Optional auth storage access is guarded, and an application error boundary offers recovery from render failures.

## Regression coverage

Tests cover access denial and valid operations, foreign-school isolation, task-board separation, private planning assets, auxiliary cache deletion/timestamp semantics, curriculum write acknowledgement, cache page reset, stale response cancellation, sparse searches beyond 800 source records, combined student class/course/status terms, request/coverage filtering, review assignment/feedback/history/read cursors and transactional workflow retries.

Production checks require all 20 configured composite indexes READY, 16 workflow query shapes and 11 student query shapes accepted against an empty isolated school scope. No real school records are changed by these probes. The release is verified only after Firebase reports deployment completion and the public version and built asset hashes match.

## Remaining validation boundary

No browser or interactive visual QA was performed. Existing lint warnings and production bundle-size guidance are reported separately from errors. A passing automated audit does not prove that an application has no remaining bugs. Local changes remain unstaged and uncommitted on main for the owner's GitHub Desktop workflow.
