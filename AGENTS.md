# Project instructions

Read `.agents/agents.md` before changing this app. It is the project's cumulative design and engineering manual. Its section 12 documents the Nature theme, dropdowns, modal layering and regression boundaries; `docs/nature-theme.md` provides the source map and renderer details.

## Required working rules

- Work in this primary checkout on `main`. Leave changes unstaged and uncommitted for GitHub Desktop. Do not create a branch/worktree or commit/push unless the owner requests it.
- Honor the owner's explicit request not to run browser testing. Use meaningful code, unit, integration/emulator, lint, build and deployment checks as appropriate; state the remaining visual verification boundary.
- Nature is an independent theme. Theme-only changes belong under `html.theme-nature`, within screen media. Do not modify other themes or lesson-plan preview/print/PDF surfaces.
- New filter menus must use `src/components/FilterSelect.jsx`, not native `<select>` menus when custom seasonal popup styling is required. Style the popup, selected/active/hover/focus states and night palette, not only the closed trigger.
- Search and filters must cover every authorized record before pagination, including older records. Never filter only loaded pages. Add matching Firestore indexes (including teacher/owner variants), test matches beyond the first page/scan, and verify production index readiness. Follow `.agents/agents.md` §12.9 for complete query, cursor, caching and regression rules.
- Full-screen dialogs and history drawers must use `src/components/DialogPortal.jsx` so their backdrop covers the sidebar and header and escapes page/card stacking contexts. Background scrolling/interaction, floating launchers, fades and Nature animation must be handled while open. Never try to fix an ancestor stacking context by only increasing a child's z-index.
- Async data must show visible initial loading, reuse verified scoped data on return visits, and update silently in real time without flashing extra loading/refreshing indicators over cached content. Gradebook and roster hooks (`useCourseRecords`, `useStudentsByIds`, `useWorkflowSearch`) must preserve in-memory cached results across unmounts so return visits render immediately without blanking the screen. Empty/missing states are shown only after acknowledged server results. Cache-only empty snapshots, pending writes, offline fallback and failed reads are not successful empty results. Retry must restart the read; denied access clears cached data and stale callbacks. Follow `.agents/agents.md` §12.11 and its required lifecycle tests.
- Result lists and pagination must never display confusing batch limits like "up to 40 per page" / "deri në 40 për faqe" that users can mistake for total page counts. When results fit on a single page, state the total results clearly (`2 rezultate`) and omit Previous/Next triggers; multi-page sets must explicitly state `rezultate në këtë faqe`.
- Scale to 50,000+ students: Never query or load the whole student directory into client state. For school-wide aggregations like Leaderboard, compute candidate ranks from course grade records in memory (`calculateCandidateRanks`) and load only top student profiles (e.g. top 50 plus authenticated student) via `useStudentsByIds`, preserving true school-wide ranks. Student directory search and export must stream page-by-page with composite indexes and incremental progress tracking.
- Blank person avatar silhouettes must be centered horizontally and vertically inside their container boxes (`.avatar` with `display: flex; align-items: center; justify-content: center;` and centered SVG margins).

- Preserve the owner's explicit action order: sharing is last in personal-plan list actions; in the editor it is immediately before the completion action, which stays last.
- Display consecutive shared-plan edits by the same actor/lifecycle as 30-minute sessions. Preserve individual immutable snapshots and keep sharing, unsharing, admin actions and system reopening events distinct.
- `public/version.json` is the release authority. Bump once after completing the change set, build/deploy manifest and assets together, wait for deployment completion, then verify the live release. A deployment does not authorize a Git commit.
